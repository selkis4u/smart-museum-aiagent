# AI Agent 설계 결정 사항

설계를 위한 확정한 값과 규칙입니다. 명세서(FR·NFR) 작성 시 이 문서를 근거로 씁니다. 용어 정의는 `CONTEXT.md`, 구조 결정은 `docs/adr/`를 따릅니다.

## 공간·판정 (CV)

- 구역 구성: 도슨트 구역 → 1차 안전선(주의) → 2차 안전선(경고)
- 도슨트 구역 기본 거리: 운영 기준 확정 ROI에서 **150cm**, 시연용 축소값은 설정 파일로 별도 관리, 유물별 조정 가능
- 탐지 학습 클래스: 쇼케이스, 테이크아웃컵 2개 (사람은 사전학습 모델 사용)
- 오픈 유물·벽 매몰 진열대는 학습하지 않고 관리자가 ROI를 직접 지정
- 관람 판정: 도슨트 구역 안에서 **2초** 이상 머무름
- 한 명이라도 안전선을 넘으면 그 구역의 도슨트 세션 전체를 멈춤
- 경고 승격: 2차 안전선 침범, 접촉 시도, 또는 주의 상태가 **5초** 이상 지속
- 해제: 침범한 관람객 전원이 1차 안전선 밖에서 **2초** 유지
- 안전선 기본 거리: 운영 기준 1차 **60cm**·2차 **30cm**, 시연용 축소값은 설정 파일로 별도 관리, 유물별 조정 가능
- 위험 단계 판정 주체: CV 모듈
- 영상 입력: 설정 파일로 실시간 웹캠·녹화 영상 파일 선택. 녹화 영상은 실제 속도로 재생(시간 기준 유지), 반복 재생으로 시나리오 테스트(FR-CV-18)
- 설치·공간 설정: CV 설정 도구(OpenCV 창)에서 바닥 기준점 4개와 감시 영역 경계 클릭(캘리브레이션), 쇼케이스 ROI 제안 확인·수정, 오픈 유물 ROI 직접 그리기, ROI마다 artifact_id 입력. 웹 편집기는 만들지 않음
- 공간 설정 파일(JSON) 하나가 공간 정보의 유일한 원본: 원근 변환 행렬, 감시 영역 다각형, 구역별 zone_id·artifact_id·확정 ROI 다각형·도슨트 구역·안전선 거리·스피커, 바닥 평면 cm 좌표. Flask는 시작 시 이 파일을 읽어 2D 맵에 감시 영역 안만 격자 + 도형으로 표시(카메라에 안 보이는 곳은 좌표가 없으므로), 웹 유물 관리에서 구역 ID·거리는 조회만. 형식은 11/11 확정

## 도슨트 (Agent)

- 해제 시 연결 멘트 후 멈춘 문장의 처음부터 재개
- 재개 전 확인: 해제 시 Vision 상황 조회로 구역에 관람객이 남아 있는지 확인, 아무도 없으면 연결 멘트 없이 세션 종료
- 반복 주의: 직전 주의 해제 후 **10초** 안에 같은 구역에서 다시 생긴 주의. 멘트 없이 조명만, 해제 시 연결 멘트 없이 재개. 경고는 반복이어도 항상 멘트를 냄
- 대체 해설: 유물마다 공식 도록만으로 만든 기본 원고를 문장별 음성 파일로 미리 저장. 첫 문장이 **5초** 안에 준비되지 않거나 생성·TTS가 실패하면(네트워크 단절 포함) 즉시 재생. 재생성·마지막 성공 원고 방식은 인터넷에 의존하므로 쓰지 않음
- 도슨트 구역에 아무도 없이 **10초** 지나면 세션 종료 후 대기. 종료 시 마무리 멘트는 없음(구역이 빈 뒤라 들을 사람이 없고, 끝까지 들은 관람객에게는 원고의 마무리 단이 끝인사)
- 세션 종료 사유 5종: 완료 후 이탈(원고 끝 뒤 구역 비움), 해설 중 이탈, 일시정지 중 이탈(해제 시 관람객 없음 포함), 대기 중 이탈(스피커 차례 대기 중), 새 세션 시작(완료 대기 중 새 관람객). 끝까지 들은 세션 = 완료 후 이탈 + 새 세션 시작
- 완료 대기: 해설 원고가 끝난 뒤 남은 관람객이 있어도 새 관람객이 관람 판정(2초)을 채우면 해설 종료 **10초** 후(이미 지났으면 즉시) 이전 세션을 기록하고 새 세션 시작. 새 관람객은 해설 종료 시점 구역 트래킹 ID 목록에 없던 ID가 2초 머문 경우로, Agent가 Vision 상황 조회로 판별
- 최신 소식(Web Search) 사용 규칙
  1. 공식 도록과 상충하면 도록 우선
  2. 신뢰 출처(언론사·기관·박물관 공식)만 허용
  3. 사용한 출처 URL을 세션 기록에 남김
  4. 같은 유물의 검색 결과는 하루 동안 캐시
- LLM: 상용 API(GPT-4o-mini 등), 스트리밍 사용.
- 웹 검색: Tavily 등 검색 API의 허용 도메인 목록으로 신뢰 출처 제한, 목록은 설정 파일로 관리
- TTS: edge-tts. 경고·주의 멘트는 미리 음성 파일로 만들어 즉시 재생

- 시연 유물: 쇼케이스 모형 = 금령총 금관(A001, 보물, 본관9663), 오픈 유물 모형 = 지장암 목조비로자나불좌상(A002, 보물, 구10416, 조선 1622년) (모두 국립중앙박물관 소장). 박스 모형에 유물 ID와 정보를 연결. A002는 2026-11-02에 석조비로자나불좌상(덕수2746)에서 교체(조성 연도·조각승·복장물 등 해설 자료가 더 풍부함)
- RAG 자료: 소장품 해설(e뮤지엄 소장품 정보 API)·박물관 공개 자료(강의 자료·도록·보도자료). A002는 본체와 함께 복장물 3건(조성기 구10417, 복장 다라니 구10422, 후령통 구10423)의 해설도 A002에 연결. 검색 혼동 테스트용 유사 유물 5점(금관총·서봉총 금관, 석조비로자나불좌상 3점: 본관1974·1975·덕수2746)과 창원 불곡사 석조비로자나불좌상 논문. 수집·청킹 코드와 결과는 `agent/knowledge/`
- RAG 청크: 청크마다 연결 유물을 `artifact_ids` 목록으로 둠(여러 금관에 공통인 내용은 여러 ID에 연결). 검색은 관람 판정 이벤트의 artifact_id로 먼저 거른 뒤 그 안에서 BM25·벡터 검색
- RAG 청크 종류: `meta`(기본 정보)·`desc`(유물 설명)·`note`(각주의 비하인드)·`background`(같은 시대 다른 유물 연구에서 가져온 시대 배경). `background`는 시대 설명에만 쓰고 해당 유물의 사실로 말하지 않음. 다른 유물 고유의 내용은 연결 없이 혼동 테스트용으로만 둠
- 자료 간 충돌: 수치·사실이 서로 다르면 현재 박물관 소장품 정보(e뮤지엄·소장품 검색)를 우선. 오래된 자료의 어긋난 내용(예: 2010년 강의 자료의 "금관 5점", 금령총 금관 지름 16.5cm)은 해설 근거로 쓰지 않음
- 해설 분량: 약 1분 30초(400자 안팎), 구성 ① 도입(이름·시대) ② 도록 기반 핵심 설명 ③ 최신 소식 1개 ④ 마무리

## 유물 ID (3모듈 공통 키)

- artifact_id는 Web 유물 관리에서 유물을 등록할 때 정함. 형식은 `A001`처럼 짧은 자체 ID, 박물관 소장품 번호는 유물 정보의 별도 항목
- 작업 순서: ① Web에 유물 등록(ID 확정) → ② Agent 도록 청크·대체 해설 파일을 같은 ID로 연결 → ③ 설치 시 ROI마다 ID를 사람이 직접 입력
- zone_id(`Z01`)는 구역을 만들 때 자동 부여, 1차는 구역 하나에 유물 하나(1:1)
- 시연 유물 ID: **A001** = 금령총 금관(쇼케이스), **A002** = 지장암 목조비로자나불좌상(오픈 유물)
- 목록에서 골라 입력하는 방식(Flask 유물 목록 조회)은 유물이 늘어나는 2차에 검토

## 기록·화면 (Web)

- 침범 기록: 침범 시작~해제를 1건으로, 최고 위험 단계와 지속 시간 포함
- 규칙 위반 기록: 침범 기록과 별도(FR-WEB-14). 같은 관람객이 같은 구역에 들어온 1회를 1건으로, 물품 종류·발생 시각 포함
- 통계표: ① 유물별 침범 횟수(주의·경고 구분) ② 시간대별(1시간 단위) 침범 횟수 ③ 유물별 평균 침범 지속 시간 ④ 유물별 관람 횟수(관람 판정 수) ⑤ 유물별·시간대별 규칙 위반 횟수 ⑥ 유물별 평균 청취 인원·끝까지 들은 비율(우선순위 하, 세션 기록의 시작·종료 인원 기준)
- 관리자 알림 시점: 경고는 좌표 메시지의 위험 단계가 경고로 바뀔 때, 규칙 위반은 규칙 위반 기록이 저장될 때
- 관리자 웹: 단일 관리자 계정 로그인 (우선순위 하), 권한 등급 구분은 범위 제외

## 시스템 구조

- CV → Agent: 이벤트 DTO, WebSocket (Agent가 서버)
- CV → Flask: 관람객 좌표와 구역별 현재 위험 단계, 초당 5회 (2D 맵·구역 색·경고 알림용)
- Agent → Flask: MCP 도구(상황 조회·조명 제어·음성 송출·기록 저장·상태 통지)가 Flask API 호출. 도구는 송용석, 도구가 부르는 Flask API는 김재원 담당
- 세션 상태(대기·해설·일시정지·재개·종료)는 Agent만 알기 때문에 상태 통지 도구로 Web에 알림
- MCP 도구 6종: Vision 상황 조회, 지식 검색, 조명 제어, 음성 송출, 기록 저장, 상태 통지
- Vision 상황 조회: Flask 상황 조회 API를 감싼 도구. CV 좌표 메시지의 최신값으로 구역별 관람객 트래킹 ID·인원·위험 단계를 돌려줌. 활용 ① 완료 대기의 새 관람객 판별 ② 재개 전 관람객 확인 ③ 세션 기록 인원(청취 통계)
- Flask → 브라우저: WebSocket
- 음성 출력(ADR-0004): Agent는 무엇을·언제 말할지만 정해 음성 송출 도구로 넘기고, TTS 변환·재생은 **Flask 서버 PC**가 재생 스레드·대기열로 맡음. 브라우저 재생은 쓰지 않음
- 즉시 정지: 위험 이벤트 시 Agent가 경고 멘트를 우선 재생으로 호출 → Flask가 진행 중 해설을 끊고 대기열을 비운 뒤 경고 먼저 재생. 반복 주의는 정지만 호출. Flask는 끊긴 문장 번호를 돌려주고 Agent는 해제 후 그 문장부터 재개
- 스피커 공유(시연): 구역→스피커 대응은 설정 파일. 같은 스피커를 쓰는 구역은 먼저 관람 판정된 구역이 차지하고, 앞 세션 원고가 끝나면(완료 대기·종료) 다음 구역 재생. 일시정지 중에는 넘기지 않음. 대기 세션은 관람 판정 즉시 스크립트·TTS를 미리 만들고, 대기 중 구역이 비면 재생 없이 종료(대기 중 이탈). 주의·경고 멘트는 구역 무관 먼저, 다른 구역 멘트로 끊긴 해설 문장은 멘트 뒤 처음부터 재생. 대기열은 Flask, Agent는 마지막 문장에 원고 끝 표시
- 규칙 위반 안내: 음성 우선순위는 주의·경고 > 안내 > 해설. 안내 멘트는 재생 중인 문장·멘트가 끝나는 즉시 끼워 넣고, 소리가 없으면 바로 재생(대기·완료 대기·일시정지·스피커 대기 모두 같은 규칙). 음성 송출 동작 4종: 해설 재생·안내 재생·우선 재생·정지
- 경고 처리 노드는 LLM 없이 규칙으로 동작, LLM은 도슨트 스크립트 생성에만 사용
- 연결 끊김(FR-WEB-16): 좌표 메시지 3초 미수신 → "CV 연결 끊김", Agent 생존 신호(상태 통지 도구, 10초 주기) 30초 미수신 → "Agent 연결 끊김" 표시. Agent는 CV WebSocket 5초 간격 재연결, 도구 호출 실패 시 1회 재시도 후 기록. 세션 동작은 바꾸지 않음
