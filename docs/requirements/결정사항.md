# AI Agent 설계 결정 사항

설계를 위한 확정한 값과 규칙입니다. 명세서(FR·NFR) 작성 시 이 문서를 근거로 씁니다. 용어 정의는 `CONTEXT.md`, 구조 결정은 `docs/adr/`를 따릅니다.

## 공간·판정 (CV)

- 구역 구성: 도슨트 구역 → 1차 안전선(주의) → 2차 안전선(경고)
- 도슨트 구역 기본 거리: 운영 기준 확정 ROI에서 **150cm**, 시연용 축소값은 설정 파일로 별도 관리, 유물별 조정 가능
- 탐지 학습 클래스: 쇼케이스, 테이크아웃컵 2개 (사람은 사전학습 모델 사용)
- 오픈 유물·벽 매몰 진열대는 학습하지 않고 관리자가 ROI를 직접 지정
- 관람 판정: 도슨트 구역 안에서 **2초** 이상 머무름
- 한 명이라도 안전선을 넘으면 그 구역의 도슨트 세션 전체를 멈춤
- 경고 승격: 2차 안전선 침범, 접촉 시도, 또는 주의 상태가 **5초** 이상 지속
- 해제: 침범한 관람객 전원이 1차 안전선 밖에서 **2초** 유지
- 안전선 기본 거리: 운영 기준 1차 **60cm**·2차 **30cm**, 시연용 축소값은 설정 파일로 별도 관리, 유물별 조정 가능
- 위험 단계 판정 주체: CV 모듈

## 도슨트 (Agent)

- 해제 시 연결 멘트 후 멈춘 문장의 처음부터 재개
- 반복 주의: 직전 주의 해제 후 **10초** 안에 같은 구역에서 다시 생긴 주의. 멘트 없이 조명만, 해제 시 연결 멘트 없이 재개. 경고는 반복이어도 항상 멘트를 냄
- 대체 해설: 유물마다 공식 도록만으로 만든 기본 원고를 문장별 음성 파일로 미리 저장. 첫 문장이 **5초** 안에 안 나오거나 생성·TTS가 실패하면(네트워크 단절 포함) 즉시 재생. 재생성·마지막 성공 원고 방식은 인터넷에 의존하므로 쓰지 않음
- 도슨트 구역에 아무도 없이 **10초** 지나면 세션 종료 후 대기
- 완료 대기: 해설 원고가 끝난 뒤 남은 관람객이 있어도 새 관람객이 관람 판정(2초)을 채우면 해설 종료 **10초** 후(이미 지났으면 즉시) 이전 세션을 기록하고 새 세션 시작. "새 관람객" 판별 기준과 알림 형식은 2주차 DTO 확정 때 정함
- 최신 소식(Web Search) 사용 규칙
  1. 공식 도록과 상충하면 도록 우선
  2. 신뢰 출처(언론사·기관·박물관 공식)만 허용
  3. 사용한 출처 URL을 세션 기록에 남김
  4. 같은 유물의 검색 결과는 하루 동안 캐시
- LLM: 상용 API(GPT-4o-mini 등), 스트리밍 사용.
- 웹 검색: Tavily 등 검색 API의 허용 도메인 목록으로 신뢰 출처 제한, 목록은 설정 파일로 관리
- TTS: edge-tts. 경고·주의 멘트는 미리 음성 파일로 만들어 즉시 재생

- 시연 유물: 쇼케이스 모형 = 신라 금관, 오픈 유물 모형 = 석조 불상류 (국립중앙박물관 소장). 박스 모형에 유물 ID와 정보를 연결
- RAG 자료: 소장품 해설·공개 도록 + 검색 혼동 테스트용 유사 유물 3~5점
- 해설 분량: 약 1분 30초(400자 안팎), 구성 ① 도입(이름·시대) ② 도록 기반 핵심 설명 ③ 최신 소식 1개 ④ 마무리

## 1차 범위 제외 (향후 계획)

- 관람객 음성 질문 응답(Q&A)
- 다국어 해설
- 관람객 수준별(어린이·성인) 해설
- 테이크아웃컵 외 금지물품(우산·셀카봉 등)
- 실물 스마트 조명 MQTT 연동 (1차는 웹 가상 조명)

## 기록·화면 (Web)

- 침범 기록: 침범 시작~해제를 1건으로, 최고 위험 단계와 지속 시간 포함
- 규칙 위반 기록: 침범 기록과 별도(FR-WEB-14). 같은 관람객이 같은 구역에 들어온 1회를 1건으로, 물품 종류·발생 시각 포함
- 통계표: ① 유물별 침범 횟수(주의·경고 구분) ② 시간대별(1시간 단위) 침범 횟수 ③ 유물별 평균 침범 지속 시간 ④ 유물별 관람 횟수(관람 판정 수) ⑤ 유물별·시간대별 규칙 위반 횟수
- 관리자 알림 시점: 경고는 좌표 메시지의 위험 단계가 경고로 바뀔 때, 규칙 위반은 규칙 위반 기록이 저장될 때
- 관리자 웹: 단일 관리자 계정 로그인 (우선순위 하), 권한 등급 구분은 범위 제외

## 명세서 양식

- 양식: 요구사항 ID, 분류, 기능명, 요구사항, 우선순위, 구현 여부 (비기능은 측정 기준 추가)
- ID: `FR-CV-01`, `FR-AG-01`, `FR-WEB-01`, `NFR-01` / 우선순위 상(핵심)·중(완성도)·하(부가 기능)

## 비기능 목표 (시연 노트북 기준, 3주차 측정 후 조정)

| 항목 | 목표 |
|---|---|
| CV 처리 속도 | 15 FPS 이상 |
| 침범 발생 → 경고 음성·조명 | 1초 이내 |
| 관람 판정 → 해설 첫 문장 | 5초 이내 |
| 관람객 위치 → 웹 맵 표시 | 0.5초 이내 |

| 침범 판정 정확도 | 시나리오 테스트 90% 이상 |

## 시스템 구조

- CV → Agent: 이벤트 DTO, WebSocket (Agent가 서버)
- CV → Flask: 관람객 좌표와 구역별 현재 위험 단계, 초당 5회 (2D 맵·구역 색·경고 알림용)
- Agent → Flask: MCP 도구(조명 제어·음성 송출·기록 저장·상태 통지)가 Flask API 호출. 도구는 송용석, 도구가 부르는 Flask API는 김재원 담당
- 세션 상태(대기·해설·일시정지·재개·종료)는 Agent만 알기 때문에 상태 통지 도구로 Web에 알림
- MCP 도구 6종: Vision 상황 조회, 지식 검색, 조명 제어, 음성 송출, 기록 저장, 상태 통지
- Flask → 브라우저: WebSocket
- 경고 처리 노드는 LLM 없이 규칙으로 동작, LLM은 도슨트 스크립트 생성에만 사용

## 이벤트 DTO 초안 (2주차 11/11에 3인 확정, 도구용 API 형식도 함께)

| 필드 | 예시 | 설명 |
|---|---|---|
| `type` | `LEVEL_CHANGE` | LEVEL_CHANGE·VIEWING_START·ZONE_EMPTY·PROHIBITED_ITEM |

| `zone_id` | `Z01` | 도슨트 구역 ID |
| `artifact_id` | `A001` | 유물 DB ID |
| `prev_level` / `level` | `NORMAL` → `CAUTION` | NORMAL·CAUTION·WARNING |
| `cause` | `LINE_1` | LINE_1·LINE_2·TOUCH·CAUTION_TIMEOUT·CLEARED |
| `visitor_ids` | `[3, 7]` | 관련 관람객 트래킹 ID |
| `timestamp` | ISO 8601 | 발생 시각 |
