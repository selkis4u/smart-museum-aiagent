# AI Agent 설계 결정 사항

설계를 위한 확정한 값과 규칙입니다. 2026-11-03 판정·기록 세부 규칙 8건(해설 전 침범 시 관람 판정 초기화, 해제 이벤트 침범자 전원, 반복 주의 기준, 트래킹 ID 끊김, 완료 대기 새 세션의 스피커 대기, 침범 기록 세션 ID·일시정지 여부, 규칙 위반 재진입 30초, Agent 재시작 시 침범 기록) 확정. 2026-11-03 보완안(침범 기록 Agent 생성, 스피커 대기 상태, 위험 이벤트 상태 무관 처리, 공통 연결 멘트, 접촉 경계, 청취 인원 정의, NFR-16·17)은 확정. 2026-11-04 측정 기준 4건(NFR-06 대상 시나리오, NFR-09 대체 해설 첫 음성 6초, NFR-13 설정값 추가, 연결 멘트 미리 생성) 확정. 명세서(FR·NFR) 작성 시 이 문서를 근거로 씁니다. 용어 정의는 `CONTEXT.md`, 구조 결정은 `docs/adr/`를 따릅니다.

## 공간·판정 (CV)

- 구역 구성: 도슨트 구역 → 1차 안전선(주의) → 2차 안전선(경고)
- 도슨트 구역 기본 거리: 운영 기준 확정 ROI에서 **150cm**, 시연용 축소값은 설정 파일로 별도 관리, 유물별 조정 가능
- 탐지 학습 클래스: 쇼케이스, 테이크아웃컵 2개 (사람은 사전학습 모델 사용)
- 오픈 유물·벽 매몰 진열대는 학습하지 않고 관리자가 ROI를 직접 지정
- 관람 판정: 도슨트 구역 안에서 **2초** 이상 머무름. 구역이 빈 뒤 다음 구역 비움까지 한 번만 보냄. 판정 전에 위험 단계가 정상이 아니게 되면(해설 전 침범) 머문 시간을 0으로 되돌리고, 해제된 뒤 다시 2초를 셈(S13)
- 한 명이라도 안전선을 넘으면 그 구역의 도슨트 세션 전체를 멈춤
- 경고 승격: 2차 안전선 침범, 접촉 시도, 또는 주의 상태가 **5초** 이상 지속
- 해제: 침범한 관람객 전원이 1차 안전선 밖에 있고 손·팔이 접촉 경계에서 떨어진 상태로 **2초** 유지 (접촉 시도는 발이 선 밖이어도 생기므로 손 조건을 함께 봄)
- 위험 단계는 해제 전까지 내려가지 않음(경고 → 주의 하향 없음)
- 해제(CLEARED) 이벤트의 `visitor_ids`: 그 침범 동안 한 번이라도 침범한 관람객 전원. 단계가 같은 채로 침범자가 늘어도 이벤트를 보내지 않으므로, 해제 때 전체 목록을 넘겨 침범 기록을 채움
- 침범자의 트래킹 ID가 끊김: 트래커가 ID를 유지하는 동안(track_buffer 2~3초)은 침범 중으로 보고, 트래커가 ID를 버리면 침범자에서 빼고 남은 관람객으로 해제를 판정
- 규칙 위반 재진입: 같은 관람객이 같은 구역을 나간 뒤 **30초** 안에 다시 들어오면 PROHIBITED_ITEM을 다시 보내지 않음(구역 경계에서 들락날락할 때 안내 연속 방지, 설정값)
- 안전선 기본 거리: 운영 기준 1차 **60cm**·2차 **30cm**, 시연용 축소값은 설정 파일로 별도 관리, 유물별 조정 가능
- 위험 단계 판정 주체: CV 모듈
- 접촉 경계: 유물 전면(쇼케이스 유리면·오픈 유물 앞면)을 CV 설정 도구에서 카메라 화면 위 다각형으로 그려 화면 좌표로 저장. Pose 손목·팔꿈치 키포인트가 다각형 안에 들어가면 접촉 시도
- 도슨트 구역 겹침: 1차는 구역끼리 겹치지 않게 설치(설정 도구가 겹침을 알려 주고 거리를 줄여 저장)
- 영상 입력: 설정 파일로 실시간 웹캠·녹화 영상 파일 선택. 녹화 영상은 실제 속도로 재생(시간 기준 유지), 반복 재생으로 시나리오 테스트(FR-CV-18)
- 설치·공간 설정: CV 설정 도구(OpenCV 창)에서 바닥 기준점 4개와 감시 영역 경계 클릭(캘리브레이션), 쇼케이스 ROI 제안 확인·수정, 오픈 유물 ROI 직접 그리기, ROI마다 artifact_id 입력. 웹 편집기는 만들지 않음
- 공간 설정 파일(JSON) 하나가 공간 정보의 유일한 원본: 원근 변환 행렬, 감시 영역 다각형, 구역별 zone_id·artifact_id·확정 ROI 다각형·도슨트 구역·안전선 거리·스피커, 바닥 평면 cm 좌표, 구역별 접촉 경계 다각형(카메라 화면 좌표). 도슨트 구역·안전선 다각형은 CV 설정 도구가 계산해 함께 저장. Flask는 시작 시 이 파일을 읽어 2D 맵에 감시 영역 안만 격자 + 도형으로 표시(카메라에 안 보이는 곳은 좌표가 없으므로), 웹 유물 관리에서 구역 ID·거리는 조회만. 세부 형식은 추후 결정(초안: 인터페이스 명세 5장)

## 도슨트 (Agent)

- 위험 이벤트는 세션 상태와 관계없이 처리: 조명·멘트·침범 기록은 대기·완료 대기 상태에서도 냄. 세션이 해설·스피커 대기 상태일 때만 일시정지로 넘어감
- 일시정지 중에도 스크립트 생성은 끝까지 마쳐 원고를 Agent가 보관하고, 송출만 멈춤(생성을 끊으면 재개할 뒷부분 원고가 없음)
- 해제 시 연결 멘트 후 멈춘 문장의 처음부터 재개. 아직 한 문장도 재생하지 않은 세션(스피커 대기 중 일시정지)은 연결 멘트 없이 처음부터
- 연결 멘트: **일시정지 시점**에 LLM 생성을 시작하고, 원고가 나오면 음성 송출 도구의 미리 변환으로 Flask가 음성 파일까지 만들어 둠. 해제되면 그 파일을 `audio_file`로 바로 재생(해제 뒤 생성·변환을 기다리지 않아 NFR-16 3초 유지). 해제 때 아직 준비되지 않았거나 생성·변환이 실패했으면, 또는 대체 해설 재생 중이면 미리 녹음한 공통 연결 멘트("다시 이어서 말씀드리겠습니다")를 재생. 반복 주의와 아직 한 문장도 재생하지 않은 세션은 연결 멘트가 없으므로 만들지 않음. 주의 → 경고 승격으로 다시 멈춰도 재개 문장이 같으면 다시 만들지 않음
- 사전 녹음 멘트: 주의·경고·안내·공통 연결 멘트 문구와 음성 파일은 Agent 담당이 edge-tts로 미리 만들어 Flask 음성 폴더에 둠
- 재개 전 확인: 해제 시 Vision 상황 조회로 구역에 관람객이 남아 있는지 확인, 아무도 없으면 연결 멘트 없이 세션 종료
- 반복 주의: 직전 침범(주의·경고 모두) 해제 후 **10초** 안에 같은 구역에서 다시 생긴 주의. 멘트 없이 조명만, 해제 시 연결 멘트 없이 재개. 경고는 반복이어도 항상 멘트를 냄
- 대체 해설: 유물마다 공식 도록만으로 만든 기본 원고를 문장별 음성 파일로 미리 저장. 첫 문장이 **5초** 안에 준비되지 않거나 생성·TTS가 실패하면(네트워크 단절 포함) 즉시 재생. 재생성·마지막 성공 원고 방식은 인터넷에 의존하므로 쓰지 않음
- 도슨트 구역에 아무도 없이 **10초** 지나면 세션 종료 후 대기. 종료 시 마무리 멘트는 없음(구역이 빈 뒤라 들을 사람이 없고, 끝까지 들은 관람객에게는 원고의 마무리 단이 끝인사)
- 세션 상태 7종: 대기·스피커 대기·해설·일시정지·재개·완료 대기·종료. 스피커 대기는 관람 판정 뒤 다른 구역이 스피커를 쓰고 있어 원고를 미리 만들며 차례를 기다리는 상태
- 세션 종료 사유 5종: 완료 후 이탈(원고 끝 뒤 구역 비움), 해설 중 이탈, 일시정지 중 이탈(해제 시 관람객 없음 포함), 스피커 대기 중 이탈, 새 세션 시작(완료 대기 중 새 관람객). 종료할 때 Agent가 음성 송출 도구의 정지로 그 구역 대기열을 비움
- 청취 인원: 세션 기록에 시작 인원, 원고 끝 시점 인원, 끝까지 들은 인원(시작 시점 트래킹 ID 중 원고 끝 시점에도 구역에 있는 인원)을 남김. 원고가 끝나기 전에 종료된 세션은 원고 끝 시점 인원·끝까지 들은 인원 0. 끝까지 들은 비율 = 끝까지 들은 인원 ÷ 시작 인원
- 완료 대기: 해설 원고가 끝난 뒤 남은 관람객이 있어도 새 관람객이 관람 판정(2초)을 채우면 해설 종료 **10초** 후(이미 지났으면 즉시) 이전 세션을 기록하고 새 세션 시작. 새 관람객은 해설 종료 시점 구역 트래킹 ID 목록에 없던 ID가 2초 머문 경우로, Agent가 완료 대기 동안 Vision 상황 조회를 **0.5초**마다 불러 판별. 새 세션을 시작할 때 다른 구역이 스피커를 쓰고 있으면 일반 관람 판정과 같이 스피커 대기로 시작
- 최신 소식(Web Search) 사용 규칙
  1. 공식 도록과 상충하면 도록 우선
  2. 신뢰 출처(언론사·기관·박물관 공식)만 허용
  3. 사용한 출처 URL을 세션 기록에 남김
  4. 같은 유물의 검색 결과는 하루 동안 캐시
- LLM: 상용 API(GPT-4o-mini 등), 스트리밍 사용.
- 웹 검색: Tavily 등 검색 API의 허용 도메인 목록으로 신뢰 출처 제한, 목록은 설정 파일로 관리
- 허용 도메인 초안(3주차 검색 테스트 후 조정): 박물관·기관 `museum.go.kr`·`emuseum.go.kr`·`khs.go.kr`·`cha.go.kr`·`heritage.go.kr`·`encykorea.aks.ac.kr`·`kci.go.kr` / 언론 `yna.co.kr`·`news.kbs.co.kr`·`imnews.imbc.com`·`news.sbs.co.kr`·`hani.co.kr`·`khan.co.kr`·`chosun.com`·`joongang.co.kr`·`donga.com`·`hankookilbo.com`·`newsis.com`·`news1.kr`
- 해제 → 재개 3초, 완료 대기 조회 0.5초, 검색 정확도(질의 20건, 상위 3개 정답 포함 90%·혼입 0건)는 확정값으로 쓰고 3주차 측정 후 조정
- TTS: edge-tts. 경고·주의 멘트는 미리 음성 파일로 만들어 즉시 재생

- 시연 유물: 쇼케이스 모형 = 금령총 금관(A001, 보물, 본관9663), 오픈 유물 모형 = 지장암 목조비로자나불좌상(A002, 보물, 구10416, 조선 1622년) (모두 국립중앙박물관 소장). 박스 모형에 유물 ID와 정보를 연결. A002는 2026-11-02에 석조비로자나불좌상(덕수2746)에서 교체(조성 연도·조각승·복장물 등 해설 자료가 더 풍부함)
- RAG 자료: 소장품 해설(e뮤지엄 소장품 정보 API)·박물관 공개 자료(강의 자료·도록·보도자료). A002는 본체와 함께 복장물 3건(조성기 구10417, 복장 다라니 구10422, 후령통 구10423)의 해설도 A002에 연결. 검색 혼동 테스트용 유사 유물 11점(D001~D005: 금관총·서봉총 금관, 석조비로자나불좌상 3점 본관1974·1975·덕수2746 / D006~D011: 교체용 유물 A003·A004의 혼동 유물, 아래 "유물 ID" 참고)과 창원 불곡사 석조비로자나불좌상 논문. 수집·청킹 코드와 결과는 `agent/knowledge/`
- 침범 기록은 Agent가 기록 저장 도구로 만듦: 침범 시작(NORMAL에서 올라감) 때 열고, 단계가 오르면 최고 단계를 갱신하고, CLEARED 때 닫음(이때 해제 이벤트의 침범자 전원으로 관람객 목록 갱신). 시각은 CV 이벤트의 timestamp를 씀. Agent가 도중에 끊기면 열린 기록은 "종료 미확인"으로 남음. Agent가 (재)시작 직후 상황 조회에서 구역이 이미 주의·경고이면 동기화 시각을 시작 시각으로 새 기록을 열고(원인 비움) 이후 CLEARED로 닫음
- 웹 글 자료: 국립중앙박물관 큐레이터 추천 등 웹 글은 `agent/knowledge/text_collect.py`로 문단 단위 청크화(A003 「백자 상감 연꽃 넝쿨무늬 대접」, 권소현 / A004 「천흥사 종」, 채해정 / A002 「목조비로자나여래좌상」, 유수란). 공공누리 제3유형(출처표시+변경금지)이라 원문 글자를 고치지 않고 청크로만 쓰고, 해설에는 사실만 가져와 새 문장으로 씀. 교육용 프로젝트 내부 사용
- RAG 청크: 청크마다 연결 유물을 `artifact_ids` 목록으로 둠(여러 금관에 공통인 내용은 여러 ID에 연결). 검색은 관람 판정 이벤트의 artifact_id로 먼저 거른 뒤 그 안에서 BM25·벡터 검색
- RAG 청크 종류: `meta`(기본 정보)·`desc`(유물 설명)·`note`(각주의 비하인드)·`background`(같은 시대 다른 유물 연구에서 가져온 시대 배경). `background`는 시대 설명에만 쓰고 해당 유물의 사실로 말하지 않음. 다른 유물 고유의 내용은 연결 없이 혼동 테스트용으로만 둠
- 자료 간 충돌: 수치·사실이 서로 다르면 현재 박물관 소장품 정보(e뮤지엄·소장품 검색)를 우선. 오래된 자료의 어긋난 내용(예: 2010년 강의 자료의 "금관 5점", 금령총 금관 지름 16.5cm)은 해설 근거로 쓰지 않음
- 기준값과 다른 청크: 원문은 고치지 않고 `agent/knowledge/corrections.json`의 주의 문구를 청크 `caution` 필드로 붙여, 해설 생성 때 근거와 함께 넘김(큐레이터 글 187cm·장렬왕후·조선 15세기, 2010년 강의 자료 지름 16.5cm·금관 5점 등)
- 기준 자료: 모든 유물의 이름·표기·수치·연도는 e뮤지엄 소장품 정보를 기준으로 함. 큐레이터 글·강의 자료·기사와 다르면 e뮤지엄을 따름(예: A002 왕비 이름 '장열왕후' - 큐레이터 글은 '장렬왕후', A003 제작 시기 15~16세기경, A004 높이 174.2cm)
- 해설 분량: 약 1분 30초(400자 안팎), 구성 ① 도입(이름·시대) ② 도록 기반 핵심 설명 ③ 최신 소식 1개 ④ 마무리

## 유물 ID (3모듈 공통 키)

- artifact_id는 Web 유물 관리에서 유물을 등록할 때 정함. 형식은 `A001`처럼 짧은 자체 ID, 박물관 소장품 번호는 유물 정보의 별도 항목
- 혼동 테스트용 유사 유물은 `D001`~`D011`로 Agent 지식 자료(`agent/knowledge/`)의 `artifact_ids`에만 쓰고 Web에는 등록하지 않음. 전시 유물이 아니라 이벤트·기록에는 나오지 않음
- 한 유물에 딸린 부속 소장품(A002의 복장물 3건)은 별도 artifact_id를 만들지 않고 A002에 연결. 청크 ID 접두어로만 `A002R1`~`A002R3`을 써서 원본 소장품을 구분
- chunk_id 형식: e뮤지엄 자료는 `<접두어>-<2자리 번호>`(`A001-03`, `A002R1-03`, 접두어는 artifact_id 또는 부속 소장품 접두어), PDF 자료는 `<자료 ID>-<3자리 번호>`(`GC2010-012`, `BG2011-001`). 세션 기록의 도록 근거에는 이 chunk_id를 그대로 남김
- 작업 순서: ① Web에 유물 등록(ID 확정) → ② Agent 도록 청크·대체 해설 파일을 같은 ID로 연결 → ③ 설치 시 ROI마다 ID를 사람이 직접 입력
- zone_id(`Z01`)는 구역을 만들 때 자동 부여, 1차는 구역 하나에 유물 하나(1:1)
- 시연 유물 ID: **A001** = 금령총 금관(쇼케이스), **A002** = 지장암 목조비로자나불좌상(오픈 유물)
- 교체용 유물: 전시 유물 교체 상황에 대비해 모형 종류별로 1점씩 지식 자료를 함께 준비(총 4점). **A003** = 백자 상감 연꽃 넝쿨무늬 대접(쇼케이스, 국보, 동원887), **A004** = 「천흥사」가 새겨진 천흥사 동종(오픈 유물, 국보, 덕수2445, 고려 1010년, 진열장 없이 전시). 출토지(박물관 기록 경기도 광주 / 천안시 주장 천안)는 견해가 갈리므로 해설에서 단정하지 않음. A004 혼동 테스트용 D009(「청녕 사년」명 동종, 신수1755)·D010(「천안광덕사」가 새겨진 동종, 동원4587)·D011(聖居山天興寺鍾銘, 본관1127) A003 혼동 테스트용 D006(같은 이름의 백자 대접 동원95)·D007(분청사기, 동원911)·D008(청자, 동원1077). 교체할 때는 CV 설정 도구에서 해당 구역의 artifact_id만 바꿈
- 목록에서 골라 입력하는 방식(Flask 유물 목록 조회)은 유물이 늘어나는 2차에 검토

## 시스템 구조

- CV → Agent: 이벤트 DTO, WebSocket (Agent가 서버)
- CV → Flask: 관람객 좌표와 구역별 현재 위험 단계, 초당 5회 (2D 맵·구역 색·경고 알림용). 전송은 Socket.IO(네임스페이스 `/cv`, 이벤트 `coords`), 메시지에 timestamp·프레임 번호·컵 소지 여부(`item_type`) 포함
- 실행 환경: CV·Agent·Flask를 시연 노트북 한 대에서 실행, 주소 `127.0.0.1`, 포트 Agent 8765·Flask 5000, 설정은 저장소 `config/`(`space.json`·`settings.yaml`). 한 PC라 시간 동기화 불필요
- `config/settings.yaml` 시간 기준값(NFR-13): 관람 판정 2초, 해제 2초, 경고 승격 5초, 반복 주의 10초, 완료 대기 10초, 구역 비움 10초, 대체 해설 전환 5초, 완료 대기 조회 0.5초, 규칙 위반 재진입 30초, CV 끊김 판정 3초, Agent 생존 신호 10초, Agent 끊김 판정 30초, CV 재연결 간격 5초. 그 밖에 허용 도메인 목록·포트·구역별 스피커 대응. 공간·거리 값은 `space.json`
- 형식 상세는 `docs/interface/interface_spec_v0.1.md` (체크리스트 9개는 11/3 결정, 나머지 세부 형식은 추후 결정)
- Agent → Flask: MCP 도구(상황 조회·조명 제어·음성 송출·기록 저장·상태 통지)가 Flask API 호출. 도구는 송용석, 도구가 부르는 Flask API는 김재원 담당
- 세션 상태(대기·스피커 대기·해설·일시정지·재개·완료 대기·종료)는 Agent만 알기 때문에 상태 통지 도구로 Web에 알림
- MCP 도구 6종: Vision 상황 조회, 지식 검색, 조명 제어, 음성 송출, 기록 저장, 상태 통지
- Vision 상황 조회: Flask 상황 조회 API를 감싼 도구. CV 좌표 메시지의 최신값으로 구역별 관람객 트래킹 ID·인원·위험 단계를 돌려줌. 응답에 구역별 재생 상태(재생 중 문장, 스피커 대기 여부, 원고 재생이 끝난 시각)도 담아 Flask → Agent 재생 상태 전달을 대신함(Agent가 해설·스피커 대기·완료 대기 중 0.5초마다 조회). 활용 ① 완료 대기의 새 관람객 판별 ② 재개 전 관람객 확인 ③ 세션 기록 인원(청취 통계) ④ 원고 재생 끝·스피커 넘겨받은 시점 확인
- Flask → 브라우저: WebSocket
- 음성 출력(ADR-0004): Agent는 무엇을·언제 말할지만 정해 음성 송출 도구로 넘기고, TTS 변환·재생은 **Flask 서버 PC**가 재생 스레드·대기열로 맡음. 브라우저 재생은 쓰지 않음
- 즉시 정지: 위험 이벤트 시 Agent가 경고 멘트를 우선 재생으로 호출 → Flask가 진행 중 해설을 끊고 대기열을 비운 뒤 경고 먼저 재생. 반복 주의는 정지만 호출. Flask는 끊긴 문장 번호를 돌려주고 Agent는 해제 후 그 문장부터 재개
- 스피커 공유(시연): 구역→스피커 대응은 설정 파일. 같은 스피커를 쓰는 구역은 먼저 관람 판정된 구역이 차지하고, 앞 세션 원고가 끝나면(완료 대기·종료) 다음 구역 재생. 일시정지 중에는 넘기지 않음. 대기 세션은 관람 판정 즉시 스크립트·TTS를 미리 만들고, 대기 중 구역이 비면(ZONE_EMPTY) Agent가 정지로 그 구역 대기열을 비우고 종료(스피커 대기 중 이탈). Flask는 구역 비움을 스스로 판단하지 않음. 주의·경고 멘트는 구역 무관 먼저, 다른 구역 멘트로 끊긴 해설 문장은 멘트 뒤 처음부터 재생. 대기열은 Flask, Agent는 마지막 문장에 원고 끝 표시
- 규칙 위반 안내: 음성 우선순위는 주의·경고 > 안내 > 해설. 안내 멘트는 재생 중인 문장·멘트가 끝나는 즉시 끼워 넣고, 소리가 없으면 바로 재생(대기·완료 대기·일시정지·스피커 대기 모두 같은 규칙). 음성 송출 동작 4종: 해설 재생·안내 재생·우선 재생·정지(구역 지정, 그 구역 해설을 끊고 대기열을 비움. 반복 주의·세션 종료에 사용). 이와 별도로 미리 변환(재생 없이 문장을 음성 파일로만 만들어 경로를 돌려줌, 연결 멘트용)
- 경고 처리 노드는 LLM 없이 규칙으로 동작, LLM은 도슨트 스크립트 생성에만 사용
- 연결 끊김(FR-WEB-16): 좌표 메시지 3초 미수신 → "CV 연결 끊김", Agent 생존 신호(상태 통지 도구, 10초 주기) 30초 미수신 → "Agent 연결 끊김" 표시. CV는 Agent WebSocket이 끊기면 5초 간격으로 재연결(Agent가 서버), Agent는 (재)연결 직후 상황 조회로 구역별 현재 위험 단계를 맞춤, 도구 호출 실패 시 1회 재시도 후 기록. 세션 동작은 바꾸지 않음

## 검토 할 사항 (CV 사항)

- 접촉 경계: CV 설정 도구에서 유물 전면을 화면 위 4~6점 다각형으로 그리고 유물 윤곽보다 약간 크게(화면상 유물 폭의 약 10%) 여유를 둠. 판정은 COCO 손목 키포인트(좌·우, 신뢰도 0.5 이상)가 다각형 안에 **3프레임 연속**(15 FPS 기준 0.2초) 들어올 때. 손목 신뢰도가 낮으면 팔꿈치로 대신 판정. 화면상 겹침 오탐을 막기 위해 그 관람객의 발 접지점이 해당 도슨트 구역 안에 있을 때만 인정
- 시연 축소값: 운영값 비율(150:60:30)을 그대로 줄이지 말고 사람 크기와 발 위치 오차 기준으로 정함. 추천 도슨트 구역 **100cm**, 1차 **40cm**, 2차 **20cm**. 11/10 촬영 영상으로 발 접지점 오차를 재서 2차 거리가 오차의 2배 이상인지 확인. 구역 겹침 금지라 두 모형 간격은 (도슨트 구역 × 2 + 모형 폭) 이상, 공간이 좁으면 도슨트 구역을 80cm로 줄임
- 트래킹 ID 오탐: ① 트래커(ByteTrack 등)의 track_buffer를 2~3초(30~45프레임)로 늘려 잠깐 가려져도 ID 유지 ② Agent는 "해설 종료 시점 목록에 없던 ID"에 더해 **구역 인원이 해설 종료 시점보다 늘었을 때만** 새 관람객으로 인정(ID만 바뀌고 인원이 그대로면 기존 관람객). 상황 조회 응답만으로 판단 가능해 추가 필드 불필요

## 이벤트 DTO 초안 (세부 형식은 추후 결정, 도구용 API는 인터페이스 명세 4장)

| 필드 | 예시 | 설명 |
|---|---|---|
| `type` | `LEVEL_CHANGE` | LEVEL_CHANGE·VIEWING_START·ZONE_EMPTY·PROHIBITED_ITEM |
| `event_id` | `evt-20261120-140321123-0001` | 이벤트 고유 ID (시각 + 일련번호) |
| `seq` | `41` | 연결마다 1부터 늘어나는 순번 (순서·누락 확인) |
| `zone_id` | `Z01` | 도슨트 구역 ID |
| `artifact_id` | `A001` | 유물 DB ID |
| `prev_level` / `level` | `NORMAL` → `CAUTION` | NORMAL·CAUTION·WARNING |
| `cause` | `LINE_1` | LINE_1·LINE_2·TOUCH·CAUTION_TIMEOUT·CLEARED |
| `visitor_ids` | `[3, 7]` | 관련 관람객 트래킹 ID |
| `item_type` | `TAKEOUT_CUP` | PROHIBITED_ITEM일 때 물품 종류, 그 외 null |
| `timestamp` | ISO 8601 | 발생 시각 |

- VIEWING_START·ZONE_EMPTY·PROHIBITED_ITEM은 `prev_level`·`level`에 그 구역의 현재 단계를 같은 값으로 넣고 `cause`는 null
- 좌표 메시지(CV → Flask)에도 `timestamp`와 프레임 번호를 넣음(NFR-04 지연 측정용)
