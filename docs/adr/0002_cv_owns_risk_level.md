# 위험 단계(주의·경고·해제)는 Computer Vision 모듈이 판정한다

CV 모듈이 안전선 침범, 접촉 시도, 주의 지속에 따른 경고 승격, 해제 대기 시간까지 규칙으로 판정하고, Agent(LangGraph)는 위험 단계가 바뀐 이벤트만 받아 도슨트 세션을 멈추고 재개한다. 안전 판단은 좌표와 시간만으로 결정되는 규칙이라 LLM을 거치면 느려지고 결과가 흔들리기 때문이다.

## Consequences

- Agent는 위험 단계를 다시 계산하지 않는다. 판정 규칙이나 기준값을 바꾸려면 CV 모듈만 고친다.
- 이벤트 DTO는 좌표 묶음이 아니라 "구역 ID, 이전 단계, 새 단계, 원인(1차/2차 안전선·접촉 시도·주의 지속), 관람객 ID, 시각"을 담는다.
- 침범 기록(시작~해제 1건)은 CV가 내보낸 단계 전환 이벤트를 받은 Agent가 기록 저장 도구로 만든다(시작 시 열기 → 단계 상승 시 갱신 → 해제 시 닫기, 시각은 이벤트 timestamp). 기록에 당시 세션 ID·세션 일시정지 여부·반복 주의 여부처럼 Agent만 아는 맥락을 담고, "Agent 판단 → 도구 → Flask" 구조(ADR-0003)를 기록에도 지키기 위해서다. Agent가 도중에 끊기면 열린 기록은 "종료 미확인"으로 남는다. (2026-11-03 변경: 이전에는 Web이 만들기로 했음)
- 해제 조건에는 접촉 시도 해소(손·팔이 접촉 경계에서 떨어짐)도 포함한다. 위험 단계는 해제 전까지 내려가지 않는다. (2026-11-03 추가)
- 단계가 같은 채로 침범자가 늘면 이벤트를 보내지 않으므로, CV는 침범 동안의 침범자를 모아 해제(CLEARED) 이벤트에 전원을 담는다. 침범자의 트래킹 ID가 끊기면 트래커가 ID를 버린 뒤 침범자에서 빼고 해제를 판정한다. 관람 판정 전에 침범이 생기면 머문 시간을 0으로 되돌린다. (2026-11-03 추가)
