# Agent가 제어의 중심이 되고, 조명·음성·기록은 MCP 도구로 실행한다

CV의 이벤트 DTO는 Agent(LangGraph)로만 보내고, Agent가 상황을 판단해 조명 제어·음성 송출·기록 저장·지식 검색을 MCP 도구로 호출한다. Flask는 이 도구들이 부르는 API와 관리자 화면만 맡는다. "보고(CV) → 판단하고(Agent) → 행동하는(도구)" 흐름을 구조 자체로 보여 주는 것이 1차 프로젝트의 목표이기 때문이다.

## Considered Options

- **MQTT 브로커**: 모듈을 독립적으로 띄우기 쉽지만 브로커를 따로 운영해야 하고 과정에서 다루지 않은 기술이다.
- **모듈끼리 각각 WebSocket**: 연결이 3개로 늘고 연결마다 서버·클라이언트를 따로 구현해야 한다.
- **Flask 허브**: 서버가 하나라 단순하고 경고를 Flask가 바로 낼 수 있지만, 판단의 중심이 Agent가 아니게 된다.

## Consequences

- 통신: CV → Agent는 Socket.IO(Agent가 서버), Agent → Flask는 Agent(MCP 클라이언트)가 MCP 서버의 도구를 부르고 MCP 서버가 Flask API를 호출, 브라우저 화면은 Flask Socket.IO. (2026-11-06 보완: MCP 서버·클라이언트 구조와 도구 호출 방식은 ADR-0005) (2026-11-05 변경: CV → Agent를 순수 WebSocket에서 Socket.IO로 바꿔 CV가 좌표 송신과 같은 클라이언트 라이브러리를 씀)
- 관람객 좌표(맵 표시용)와 구역별 현재 위험 단계는 판단이 필요 없으므로 CV → Flask로 직접 보낸다. Web은 이 값으로 구역 색과 경고 알림을 표시한다.
- 세션 상태(대기·스피커 대기·해설·일시정지·재개·완료 대기·종료)는 Agent만 알기 때문에 상태 통지 MCP 도구로 Flask에 알린다. (2026-11-02 추가, 2026-11-03 상태 목록 보완)
- 침범 기록도 Agent가 기록 저장 도구로 만든다(ADR-0002). (2026-11-03 추가)
- 경고가 Agent를 거치므로, LangGraph의 경고 처리 노드는 LLM을 호출하지 않는 규칙 노드로 만든다. 위험 이벤트가 오면 해설 송출을 끊고 즉시 조명·경고음 도구를 호출한다. 스크립트 생성은 끝까지 마쳐 보관해 재개에 쓴다(2026-11-03 변경: 생성까지 끊으면 재개할 뒷부분 원고가 없음). 세션이 없는 대기·완료 대기 상태에서도 위험 이벤트의 조명·멘트·기록은 똑같이 처리한다. LLM은 도슨트 스크립트 생성에만 쓴다(생성 중 지식 검색 도구 선택 포함, ADR-0005).
- Agent가 멈추면 경고도 멈춘다. 시연 규모에서는 감수하며, 운영 단계에서는 Flask가 CV 이벤트를 직접 받아 경고를 내는 예비 경로를 검토한다.
- 스마트 조명 MQTT 연동은 2차 실물 조명 단계로 미루고, 1차는 웹 가상 조명으로 시연한다.
