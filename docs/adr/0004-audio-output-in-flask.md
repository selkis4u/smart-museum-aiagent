# 소리는 Flask 서버 PC가 내고, 해설 정지는 Agent가 음성 송출 도구로 건다

Agent는 무엇을 언제 말할지(해설 문장, 주의·경고 멘트, 재개 위치)만 정해 음성 송출 도구로 넘기고, 실제 TTS 변환과 재생은 Flask 서버 PC가 재생 스레드와 대기열로 맡는다. 위험 이벤트가 오면 Agent가 경고 멘트를 우선 재생으로 호출하고, Flask는 진행 중인 해설을 즉시 끊고 대기열을 비운 뒤 경고를 먼저 재생한다. 조명과 같은 "Agent 판단 → 도구 → Flask 출력" 구조를 소리에도 그대로 적용하기 위해서다. (2026-11-02)

## Considered Options

- **관리자 브라우저 재생**: HTML5 Audio로 쉽지만 관리자 화면이 열려 있어야 하고 브라우저 자동재생 차단이 있으며, 관람객용 출력이 관리자 화면에 묶인다.
- **구역 스피커 전용 웹 페이지**: 운영 설계(구역별 고정 스피커)와 가장 비슷하지만 1차 시연에는 과하다. 2차 확장 후보.
- **Flask가 위험 단계를 보고 스스로 정지**: CV 좌표 메시지로 더 빨리 끊을 수 있지만 정지 판단이 Agent와 Flask 두 곳으로 나뉜다.

## Consequences

- 음성 송출 도구(=Flask 음성 API)는 네 가지 동작을 가진다: 해설 문장 재생(대기열에 추가), 안내 재생(재생 중인 문장·멘트가 끝나면 끼워 넣고 소리가 없으면 바로, 규칙 위반용), 멘트 우선 재생(해설을 끊고 먼저 재생), 정지(멘트 없이 끊기, 반복 주의용). 우선순위는 주의·경고 > 안내 > 해설. (안내 재생은 2026-11-02 추가)
- Agent는 문장을 스트리밍으로 미리 보내므로 대기열에 여러 문장이 쌓일 수 있다. 우선 재생·정지 시 Flask는 대기열을 비우고 끊긴 문장 번호를 응답으로 돌려주며, Agent는 이 번호를 재개 위치로 쓴다.
- 침범 → 경고 1초(NFR-02)에는 CV → Agent → Flask 음성 API → 재생 시작 전 구간이 포함된다. 3주차 측정 대상.
- 요청·응답 형식은 2주차 도구용 API 확정(11/11) 때 정한다.
