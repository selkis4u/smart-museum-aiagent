# MCP 도구는 MCP 서버로 제공하고, 해설 근거는 LLM이 고르고 위험 대응은 규칙 노드가 부른다

도구 6종(Vision 상황 조회·지식 검색·조명 제어·음성 송출·기록 저장·상태 통지)을 Agent 안의 함수가 아니라 **MCP 서버**로 제공하고, LangGraph Agent는 **MCP 클라이언트**로 서버에 연결해 도구 목록을 받아 쓴다. 호출은 두 갈래로 나눈다. 해설 생성 단계에서는 **LLM이 Tool Calling으로** 지식 검색 도구(도록 보강 검색·최신 소식 검색)를 고르고 질의를 정한다. 위험 대응·세션 제어는 **규칙 노드가 같은 MCP 도구를 코드에서 직접** 부른다. (2026-11-06)

기존 설계(ADR-0003)는 어떤 도구를 언제 부를지를 상태 전이표가 모두 정하고, 도구는 Flask REST API를 감싼 함수였다. MCP는 모델이 도구를 발견하고 선택하도록 연결 방식을 표준화한 프로토콜이라, 이 구조에서는 MCP가 하는 일이 없고 이름만 MCP였다. 판단이 필요한 곳은 LLM이 도구를 고르고, 안전이 걸린 곳은 규칙으로 고정해야 "보고 → 판단하고 → 행동하는" Agent 구조와 경고 1초(NFR-02)를 함께 지킬 수 있다.

## Considered Options

- **MCP를 빼고 일반 함수(REST 클라이언트)로 부름**: 가장 단순하고 지연이 없지만, 기획서의 Agent 도구 표준화 목표가 사라지고 LLM은 문장만 쓰게 된다.
- **모든 처리를 LLM이 도구를 골라 수행(ReAct)**: Agent다운 구조지만 경고·조명이 LLM 응답 시간과 판단에 묶여 NFR-02 1초와 안전 동작을 보장할 수 없다.
- **혼합(채택)**: 연결은 전부 MCP로 통일하고, 선택 주체만 단계별로 나눈다.

## Consequences

- **MCP 서버**(송용석, `agent/mcp_server/`): Python MCP SDK(FastMCP)로 도구를 이름·설명·입력 스키마와 함께 정의한다. 지식 검색은 로컬 검색기(`agent/retrieval/`)와 웹 검색 API를, 나머지는 Flask 도구용 API(인터페이스 명세 4장)를 부른다. Flask API의 형식과 담당(김재원)은 바뀌지 않는다.
- **연결 방식**: 한 PC 시연이므로 stdio. Agent가 시작할 때 MCP 서버를 자식 프로세스로 띄우고, `langchain-mcp-adapters`로 도구 목록을 LangGraph 도구로 불러온다. 통신은 MCP 규약(JSON-RPC)이다.
- **LLM이 고르는 도구**: 스크립트 생성 작업에서 LLM에 `search_catalog`(도록 보강 검색)·`search_news`(최신 소식 검색)만 연결한다. 기본 근거는 근거 캐시에서 프롬프트에 미리 넣고, LLM은 보강 검색이 필요한지·최신 소식을 찾을지·어떤 질의로 찾을지를 정한다. 도구 라운드는 한 번(여러 도구 동시 호출 가능)으로 제한한 뒤 바로 스트리밍 생성한다. LLM이 `search_news`를 부르지 않거나 검색이 2초를 넘기면 최신 소식 없이 생성한다(기존 규칙과 같음).
- **규칙 노드가 직접 부르는 도구**: 조명 제어·음성 송출·기록 저장·상태 통지·Vision 상황 조회. `risk_rule`·`notice_rule`·세션 시작·종료 노드가 정해진 인자로 MCP 클라이언트의 도구 호출을 한다. LLM을 거치지 않으며 경고 처리 원칙(FR-AG-10)은 그대로다.
- **지연**: 해설 생성에 도구 선택용 LLM 호출이 한 번 늘어난다. 첫 문장 5초 타이머(관람 판정 시각 기준)는 그대로 두고, 3주차에 측정한다. 5초를 지키지 못하면 `settings.yaml`의 `tool_choice: llm | fixed`를 `fixed`로 바꿔 코드가 정해진 질의로 `search_news`를 부르는 방식으로 되돌린다(도구 연결은 MCP 그대로). stdio 도구 호출의 추가 지연은 수 ms 수준으로 예상하며 NFR-02 측정 때 함께 확인한다.
- **장애 처리**: MCP 서버 프로세스가 끊기면 Agent가 다시 띄운다. 도구 호출 실패는 기존 규칙대로 1회 재시도 후 기록한다.
- **문서**: 기획서 v0.8, 요구사항 명세서 v0.5(FR-AG-15), 분석서 v0.5(2.2·5.3), 결정사항 시스템 구조, 상태도 v0.3(6.3), 인터페이스 명세 0장·4장에 반영한다.
